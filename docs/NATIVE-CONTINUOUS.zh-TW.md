# 原生連續攻擊與跨場次

原生視窗以按住 Space 連續近身攻擊目前目標。每次請求都經既有 C17 與有界 transport；下一次必須等到自己的正式攻擊回覆、目前動作完成，且 frame 與 World 的身份、動作及世界世代相符。沒有用鍵盤自動重複頻率決定攻擊速度。

`native_combat::HeldAttack` 保存一次實際按下的目標、GAME epoch、世界世代、權威修正計數及前次請求時的攻擊計數。視窗和 CLI 戰鬥驗證共用 `LoginController::continue_attack`。放開 Space、方向鍵移動、點選目標、Esc、失焦、取消或關閉會清除連打；目標消失／死亡／離開近身距離、自己死亡、移動限制、結算、世代或權威位置修正也會清除。清除後的遲到回覆不會重新啟動。

未收到回覆仍使用既有兩秒逾時，連打立即退休，需再次實際按下才能重試。移動輸入會中止連打，並等待已送出的攻擊回覆與動作完成後才移動。已送出的封包不能撤回；停止表示不再排入下一次。遠距離追擊與遠程攻擊未接線。

## 隔離驗證

`維護工具/verify-native-combat.ps1` 執行原有四案例及新增 `room-world-cycle`；`-CycleOnly` 可單獨跑跨場次。所有情境仍使用固定正式 JAR 的真正 LOGIN／GAME ClientSession、記憶體帳號和原始遊戲資源，不存取 SQL、玩家實表或正式程序。

- 一次攻擊／勝利：共用連打控制送出第一次後模擬放開，沒有額外攻擊。
- 自然敗北：一次按住後由共同控制排下一次，正常角色 50 HP 與 Bot 100 HP，直到正式死亡、原動畫完整停留、一次 E0 及返回。
- 無回覆：對維修 NPC 一次按住只送一次，逾時後不自動重試；第二次實際按下可送出，仍不虛構命中或 HP 變化。
- 跨場次：同一 GAME epoch 完成兩次正常敗北及返回，中間重新入房／準備。第二場重新核對 HP=50、攻擊數及死亡確認數為零、結果與計分為空、角色存活、回饋 Idle。世界世代遞增；舊死亡 frame 不能授權新世界，第二場首幀為待機且沒有前場音效。兩場最後都確認死亡一次並完成返回。

Rust 測試涵蓋回覆與動畫雙重門檻、放開後停止、逾時與遲到回覆、重新按下，以及 11 種 owner／世界／目標／權威中止條件。GUI 的鍵盤事件接線已建置；上述 CLI 共用控制測試不能代替實際鍵盤、焦點、DPI 或音效裝置驗收。
