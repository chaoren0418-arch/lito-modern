# #140 T026（M2 1/2）：技能狀態表 `docs/SKILLS-STATUS.md`

## 做了什麼
- 新增 `docs/SKILLS-STATUS.md`。181 個技能逐列，共 15 欄：ID、名稱、常數、職業、記錄類型、尾段形狀、目標、是否需要 Ctrl（E149）、成本、訊息、客戶端、送包測試（狀態）、資源／特效核對、分類、備註。
- 文件另有以下各節：
  - 分類規則與伺服器缺口組對照（T021–T025、T028 六組）；
  - 表外的訊息 ID（278、279、299、1412、1339）；
  - 其他判定（材料 25／58、4016、武器 Proc、卡瑞／莎爾與 map1005、技能 68 生命週期）；
  - 保留槽 39；
  - 技能別名 7。

### 第 2 次修正（審查退回 5 點＋1 建議）
1. **測試欄**：掃描規則改成四種傳 ID 方式（字面、迴圈、欄位、常數），規則寫在文件「來源與方法」。
   - 結果：38 個技能有送包測試，其中 **11 個已執行通過**（14、26、31、32、42、49、52、54、72、78、206），來源是白名單的 `native_selector_only`、`native_ability_buffs` 測試，#101 76／76。
   - 原本「目前沒有任何技能已執行通過」的說法是錯的，已更正。
2. **T026 指定項目**：
   - 訊息 ID 另立一節，每個都附出處。
   - 技能 90：判定仍為可驗。理由是裝備模式只在隔離候選，E149 照自身行為驗；理由寫在備註。
   - BUFF 3／151：判定仍為可驗。理由是伺服器已停用 SQL 覆寫、保留既有行為；理由寫在備註。
   - 武器 Proc、材料 25／58、4016、卡瑞／莎爾、技能 68 生命週期，都寫進「其他判定」或備註。
3. **Ctrl 欄**：改為逐列回答 E149 下是否需要 Ctrl，四種值：不適用、依目標而定、不需要，以及 26／42／68 的特別說明。
4. **缺口組**：補上 T021–T025、T028 的對照表，並寫明 T021、T028 不改變分類的理由。
5. **本報告**：如實列出未完成的項目，見「待驗證」。
6. **建議項**：加了「資源／特效核對」欄，目前全部是「待核對」。

## 推測
- 經過多層函式才傳到 request 的技能 ID，掃描仍可能漏抓。
- 「卡瑞／莎爾屬於 BATTLE 模式 NPC 對話」是依伺服器文件的描述推得，沒有讀 map1005 的資料。
- 表外訊息 ID 的情境大多出自伺服器隔離候選的紀錄，E149 是否送同樣的 ID 還沒驗證。
