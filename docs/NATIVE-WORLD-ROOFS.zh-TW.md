# 原始屋頂與遮擋群組

現行世界場景已接入 S32 Layer5 控制的半透明／完全隱藏群組。群組不一定是屋頂，也可能是樹、牆或大型裝飾；實際作用範圍由原始地圖決定。原版 BIN 未執行，共用資源與相鄰專案保持唯讀。

## 來源與執行路徑

`native_multisector_scene` 將 Layer4 的來源群組 ordinal 留在地圖分片上，不能改用序列化 group ID。Scene 載入時建立屋頂定義，並為受控圖格保留原始 RGB555 coverage；特效 TIL 在漸變時需要原始 coverage，不能拿已轉成預覽 alpha 的像素反推。這些快取受原有資料與 64 MiB prepared terrain 上限限制，載入與合成可取消。

`native_world_roofs` 以本地角色的邏輯格座標查 Layer5，精確轉換到 native half-cell。相機位置與人物顯示內插不控制屋頂。座標包含現行導航已檢查的本地預測位置；收到伺服器修正後依更新座標重選群組，不寫入世界權威狀態。

漸變使用每 50 ms、每次 4 級、0～31 權重的 RGB555 參照；穩定半透明使用分量平均，並非固定 16/31。離開會回復來源正常／基礎半透明狀態，中途反轉從當前權重繼續。長時間停頓只需有限步數追上，不建立無界 timer 工作。世界世代、角色 ID、角色 incarnation 或地圖 geometry digest 改變會清除舊群組；不同地圖的屋頂 Frame 不能傳給現行合成器。

屋頂、地形、本體、附件與陰影共用現行分片深度排序。完全遮蔽的來源會覆蓋底下 owner；半透明與漸變保留底下像素 owner，完全隱藏群組不提交。選取因此沿用同一畫面像素表。

## 原始位元組證據

`驗證紀錄/current/native-world-roofs/native-roof-raw.json` 保存固定 PE SHA256、各地址的位元組及獨立 Capstone 解碼。0x483890 使用 0x62F3AC 表的 kind0→flag1、kind1→flag2；0x48AFC0 依舊位置與本地角色 +0x2C／+0x30 選取群組。0x432F70／0x4330D0 包含步長4及50ms排程，0x488DAD 為繪製旗標優先序，0x4C1A17 為權重表證據。

獨立 Python 盤點全部 495 個 LTmap S32，共讀取 52,285,859 bytes：有效座標內只有 kind0／1，群組引用皆合法；49,975 筆區塊外紀錄依載入規則略過，不捲入鄰接區塊。這項盤點只證明 metadata 範圍，不等於全部地圖已通過渲染驗收。

## 驗證範圍

六項 Rust 測試檢查群組 ordinal、半格與區塊邊界、非法資料、漸變進出／反轉、身份與地圖切換、倒退時鐘、取消，以及世界狀態不被顯示處理修改。

真實 LTmap 564 有390筆 Layer5、369個有效觸發格、49個群組；八張時點圖逐像素比對獨立 scalar RGBA 與 owner 表。樣本可見本體像素118→778→118。真實 LTmap 565 的四區塊有1,056筆 Layer5、682個有效觸發格、17個群組、354筆區塊外紀錄；六張完全隱藏／回復時點圖同樣逐點比對，樣本454→778→454。

Python 獨立讀取原始 S32 bytes 並重播 clock，另核對資源 pins、十四張 PNG，以及整套回歸中20個世界案例的角色身份、座標、elapsed clock 和群組狀態。既有八張地形／本體、六張角色附件／陰影與六張背包圖示仍保留各自比對。

本階段完整 gate 為同一 Debug x64 EXE 的167 Rust／31組、52隔離TCP、34靜態像素比對。最終結果以 `驗證紀錄/current/native-world-roofs/` 的 `summary.json`、`roofs-receipt.json`、`final-state-check.json` 為準；Release 只有編譯檢查。

## 尚未完成

這是依已核實來源規則實作的 elapsed-time catch-up；未重建原版 timer queue 的排程延遲及多群組共用 tile pointer 的 alias 行為。SPR／TIL 解碼器共用，scalar 合成與 Python clock replay 才是獨立路徑；RGB555 參照不代表原版 RGB565 framebuffer 像素等價。完整動態角色旗標、特效交錯、原版插入時序、GUI／IME／DPI、音效裝置及完整玩家流程仍待驗收。

本輪最終結果：167 Rust／31組、52隔離TCP、34像素比對皆通過。20個世界案例共873個影格的屋頂狀態獨立重播一致，但這些TCP路線沒有進入屋頂觸發格（active roof frames=0）；實際半透明／隱藏觸發的證據是兩張原始地圖的14張CPU合成樣本與Model測試，並未宣稱連線路線或GUI已驗收屋頂進出。

## 物件遮擋開關：list.spr `100.switch`（2026-11-12，#338）

除了 S32 Layer5，原版還有第二種「本地角色站到指定格就變半透明」的來源：物件 sprite 自己的 list.spr 屬性 100。這條路徑以前沒有接，#338 補上。

- 來源規則（靜態反組譯，未執行原版；映像 SHA256 `4271D92F…5C2AB6E9`）：
  - `43E377` 把屬性 100 讀成 `count` 與 `count` 組 `x0 y0 x1 y1`，存進每個 sprite 的表（`647E80`）。
  - `4E6C50` 在每個 S_PUT_OBJECT 之後執行：對每個矩形，y 從 `actor+30 + y0` 到 `+ y1`，x 從 `actor+2C + x0` 起每次加 2 個 native half-cell 到 `+ x1`，用 `483890` 以 kind 2（表 `62F3AC` → 旗標 5）把這個物件登記到該格。
  - `48AFC0` 只有三個呼叫點：本地角色步進（`4E2F2F`）與 S_PUT_OBJECT（`4E7F5D`、`4E7F9A`）。它比對本地角色的 half-cell；帶 bit 4 的登記走 `4E6B90(actor, 1)`／`4E6BF0(actor)`，經 `4CDAF0` 把本體（`+84`）、陰影（`+88`）與附件（`+8C` 陣列）的片段旗標改成 `(flags & !3) | 值`，`actor+1A` 保存這個值。
  - `488DD0` 把旗標 `0x101` 送到穩定半透明寫入器（與屋頂穩定半透明同一支）。這條路徑不經過 `433210`／`433460`，所以沒有 50 ms 漸變。
- 現行實作：`native_actor_switch` 解析屬性 100，`native_world_scene` 每幀以「物件邏輯格」與「本地角色邏輯格（含已接受的預測步）」判斷，成立時把該物件以既有的 `Style::Half` 呈現（本體與一般附件半透明、旗標 8 的附件維持 screen、陰影不變）。觀戰者沒有本地角色，不觸發。屬性格式不合時不套用，並在 actor receipt 的 `occlusion_switch.error` 留下原因。
- 與 LiTo 的關係：共用 list.spr（SHA256 `523C61AD…E8B9F127`）有 196 個 sprite 帶屬性 100，清單在 `docs/reports/issue-338/list-spr-switch.tsv`。競技場門是 `#2083`（伺服器 `BattleDoor.GFX = 2083`），內容 `100.switch(1 -2,0,2,0)`：本地角色站在門所在格或左右相鄰格（同一個 y）時，門以半透明繪製。
- 與原版仍有的差異：現行是兩個座標的純函數，對 S_PUT_OBJECT 之後不再移動的物件（門）與原版的登記結果相同；會移動的 switch 物件（船）在原版的重新登記時機沒有還原。x0 為奇數的矩形登記的是兩個整格之間的 half-cell，角色站不到，現行同樣不觸發。離開後原版把陰影旗標從 5 改成 4 的後果沒有追（競技場門沒有陰影）。`actor+1A` 在之後影格插入時的讀取點沒有逐一追。

## CI 可重跑的合成場景（2026-11-12，#338）

`src/modern_lito/native_world_occlusion_tests.rs` 用測試內撰寫的兩個相鄰 S32 區塊與 TIL 位元組，走現行正式路徑（`WorldMap` → 靜態參照與群組收集 → `Scene` → Layer5 屋頂 runtime → 以錄製的 S_WORLD／S_STATUS／S_PUT_OBJECT 建立的 `World` 加預測步 → 分片 raster），不需要客戶端資源，GitHub Actions 的 `cargo test --lib` 會跑：

- 區塊接縫：西區塊的屋頂群組有一片磚寫在 local x=128（落在東區塊），它跟著西區塊的群組變化；同一片磚改寫在東區塊時畫面相同但不屬於西群組。區塊外的 Layer5 紀錄（x≥128）不捲入鄰區塊。群組以區塊內序號連結，不看序列化 ID。
- 屋頂進出：角色從屋外走進半透明觸發格、同群組第二格（不重新起算）、跨過接縫離開（權重 17 起回復）、走進完全隱藏觸發格、再離開（權重 1 起回復）；每一步核對群組狀態與取樣像素（RGB555 平均／權重公式），以及本體是否擁有該像素（半透明與漸變保留、回到不透明後被屋頂取走、沒被控制的牆一直遮住）。
- 新的 S_PUT_OBJECT 是新的 incarnation，屋頂從頭起算；呈現不改寫 World。
- 地形常駐視窗：以 8×8 格區塊載入的視窗場景，在該區塊四角與中間的相機下，與整張地圖的合成結果逐位元組相同。

這些是合成資料，證明的是規則與接線，不是任何一張正式地圖的畫面；真實地圖仍以 `tests/native_world_roofs.rs`（需要本機客戶端資源）與實機為準。

- 連線路線與 GUI 的屋頂進出、門的半透明仍沒有實機證據（GUI 清單 W13、W14）。
