## S10 訊息代碼（4A4670，格式 `hc` 加字串）

1. 代碼小於 `string-c` 列數：用 4A44D0 展開後以調色盤 24 寫入聊天區。
2. 否則 `代碼 − 2000` 小於 `LTstring` 列數：`sprintf(LTstring[列], …)`，引數直接從封包讀，形狀依列而定（表 4A4BAC）：

   | 列 | 引數 |
   |---|---|
   | 110、186、268、285、286 | 一個 32 位元數字 |
   | 249、252、254、258、259、260、263、266 | 一個字串 |
   | 261、262 | 兩個字串 |
   | 276 | 一個字串，先做 `$n` 展開（4D44A0） |
   | 其他 | 沒有引數 |

3. 兩張表都沒有：不顯示。

4A44D0 的規則：

- `%0`–`%9`：插入第 n 個引數（先做 `$n` 展開）；引數不夠時不輸出。
- `%d`、`%o`、`%s`：韓文助詞位置，只有 code page 949 才輸出；CP950 不輸出任何字。
- `%` 後面接其他字元：只輸出那個字元（所以 `%%` 是 `%`，`%n` 是 `n`，不是換行）。

特殊代碼：834 和 875 走各自的分支後直接返回，不顯示文字（834 推測是開倉庫密碼畫面，875 推測是完整性檢查回應）。73 在旗標 `byte_63DF4C` 設定時略過一次；81 在區域 5 有額外條件；153、286、288 顯示文字之外還呼叫 487600（推測是禁言計時）。後面這三類的附帶行為本專案沒有重現，文字照常顯示。

數字引數的 LTstring 列（110、186、268、285、286）：世界封包讀取器把 S10 的引數都當字串讀，沒有保留原始位元組，所以這幾列不顯示。lito-launcher-server `origin/main` 的 `ClientSession.java` 沒有送出 2000 以上的代碼。
