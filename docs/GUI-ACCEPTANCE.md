### 1.1 數值 schema 與登入器的啟動方式

**已驗證（靜態讀原始碼）：**
- 伺服器的數值 schema 由程序啟動時的系統屬性 `-Dlito.numeric.breakthrough` 或環境變數 `LITO_NUMERIC_BREAKTHROUGH` 決定，1–4 有效，其他值是 0；封包上沒有協商（`docs/PROTOCOL-CONTRACT.md` §6.2「數值 schema」）。
- **登入器啟動本機伺服器時會帶 schema 4**：`LauncherSettings.cs:54` 的 `NumericBreakthroughEnabled` 預設 `true`，`MainForm.cs:290`、`:296` 載入時又設成 `true` 並勾選；`LocalServerService.cs:228-231` 對伺服器程序設 `LITO_NUMERIC_BREAKTHROUGH=4`（`LauncherService.cs:18`）。以上讀自 lito-launcher-server `origin/main` `e6b8539e`。
- 伺服器獨立啟動（`Start-LiTo381-Server.bat` → `tools/Start-LiToServer.ps1`）不設這個變數（兩個檔案搜尋 `numeric`／`breakthrough` 都沒有結果），所以是 schema 0，除非啟動它的命令列視窗本身已經帶了這個環境變數。
- **重建版客戶端目前只接受 schema 0**：`native_status_receipt.rs:29` 要求 `S_STATUS` body 剛好 37 bytes；`native_world.rs:1358-1360` 把 `S_HIT_POINT`／`S_MANA_POINT` 讀成兩個 `h`（5 bytes）。schema 1–4 的 48／66／78 bytes 與 9 bytes 會被當成協定錯誤。這與 `docs/G01-G12.md` G05.1 的 remaining「當前原生入口仍明確限定 schema0」一致。

**所以 T030 的伺服器要這樣啟動：**
1. 不要用登入器的「啟動本機伺服器」。
2. 開一個新的命令列視窗，先確認沒有殘留變數：PowerShell 執行 `$env:LITO_NUMERIC_BREAKTHROUGH` 應該沒有輸出（cmd 執行 `echo %LITO_NUMERIC_BREAKTHROUGH%` 應該原樣印出 `%LITO_NUMERIC_BREAKTHROUGH%`）。
3. 在同一個視窗用伺服器自己的啟動入口啟動（伺服器 repo 的 `Start-LiTo381-Server.bat`；先跑 `--check` 預檢）。
4. 進入世界後，HP／MP 顯示的是伺服器上的實際值（見 W01），就表示 schema 相符。

**待驗證：** 連到 schema 4 伺服器時，客戶端畫面實際顯示什麼（N02）；E149 部署包的啟動入口檔名是否和 `origin/main` 相同。

## 17. 聊天（T060）

依據：`CLAUDE.md` 目標列有「聊天」；TASKS T060。**現況（#342，程式已接、畫面未驗）**：原生視窗多了聊天面板（`native_chat_window.rs`），規則在 `native_chat.rs`。`chat_window.rs`、`direct_chat_window.rs` 是舊的 Modern profile 視窗，和原生入口無關，它們的 GUI 測試仍是 ignored。

操作方式：
- 進入大廳、房間或場景後，視窗會出現「聊天」按鈕（場景中在右上角「寵物／召喚物」下方；大廳與房間在右下角）。有未讀訊息時按鈕文字是「聊天（新訊息）」。
- 按下後整頁換成聊天面板：上方是訊息紀錄；「顯示」那一列有七個勾選框（一般／大喊／全體／買賣／密語／NPC／其他）；再下面是頻道下拉（一般／大喊／全體／買賣／密語）、「密語對象」欄、訊息欄與「送出」；最下面一行是提示文字。按「回到畫面」離開面板。
- 背包、租裝對話、寵物面板、房間工具開著的時候沒有「聊天」按鈕。

預期是依 E149 伺服器的實際行為寫的（`docs/PROTOCOL-CONTRACT.md` §6.2）。**玩家聊天的收件人是同頻道／同房間／同租裝村／同 WORLD 地圖的人，和距離無關**；8 格與 50 格只用在 NPC 說話。
